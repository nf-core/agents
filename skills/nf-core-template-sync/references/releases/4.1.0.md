# nf-core/tools 4.1.0

Community knowledge for the 4.1.0 template sync that is not in the blog post (https://nf-co.re/blog/2026/tools-4_1_0). Per-path sections go into the worklist entry for that file.

## Known tool problems

- `nf-core modules update` (4.1.0) rewrites `conf/containers_*.config` with only the modules that it updated. All other process entries disappear. `finalise.py regenerate` discards those files and regenerates all container configs in a separate step.
- The `container_configs` lint test (4.1.0) compares the generated files with the git index, and in check mode it restores the committed files. Commit regenerated configs before you run lint again. The fix (nf-core/tools#4301) is on the tools `dev` branch, not yet in a release.
- tools 4.1.0 lint runs `nextflow config -o json`. With Nextflow before 26.04.7, this fails on a `publishDir` list of maps that contain closures (`No such variable: task` or `meta`; nextflow-io/nextflow#7474, fixed in 26.04.7 and 26.10.0). Use a fixed Nextflow version. Do not change `publishDir` only to make lint pass: one AI fix (nf-core/detaxizer#103) removed `${meta.id}` from output paths, and a reviewer had to catch it.

## `subworkflows/local/utils_nfcore_*_pipeline/main.nf`

- 4.1.0 adds a last argument to the `UTILS_NFSCHEMA_PLUGIN` call. Use `false` until the pipeline uses typed parameters (discussion in nf-core/viralmetagenome#321).
- A trailing comma after the last argument is valid syntax (discussion in nf-core/sarek#2272).

## `CHANGELOG.md`

- The template header now has `<!-- TODO nf-core: replace with date on release -->`. Keep the pipeline header. Add the TODO comment only if the pipeline header already has one.

## `conf/igenomes.config`

- 4.1.0 changed this file from block syntax (`params { genomes { 'GRCh37' { fasta = "..." } } }`) to map syntax (`params.genomes = [ 'GRCh37' : [ fasta : "...", ... ], ... ]`).
- Take the template file. If the pipeline added keys or genomes, add them back in map syntax: `key : value` entries, separated by commas, inside `[ ]`. Check the Nextflow config docs, and set `needs_review`.

## `conf/modules.config`

- The template changed the `MULTIQC` `publishDir` setting (nf-core/tools#4347). Apply the same change where the pipeline configures `MULTIQC`, and keep all other pipeline settings.

## `.github/actions/nf-test/action.yml`

- Take the template version. It reverts the `setup-apptainer` pin from 4.0.3. maxulysse advised against other pins (nf-core/mag#1104).

## `tests/nextflow.config`

- The template simplified `pipelines_testdata_base_path` (nf-core/tools#4285). Take it only if `conf/test*.config` does not add a pipeline path to it. nf-core/crisprseq adds `crisprseq/...`, so the template value would break its test data URLs. Keep the pipeline parameters.
